## EGG_C7 (C7h / 199) – інтерактивний класичний Pong

Це демо — проста іграбельна гра Pong, яка демонструє, як за допомогою кількох [спрайтів](../2-3_sprite-subsystem.md) та [2DPT](../2-4_2dpt-introducing.md) можна створити майже повноцінну гру. Дві ракетки та м'яч реалізовані трьома окремими спрайтами, а ігрове поле, центральна лінія та рахунок створюються командами 2DPT.

Три спрайти: ракетки є прямокутниками **12**×**48** пікселів, а м'яч — прямокутником **12**×**6** пікселів. Вони збережені в офлайн-режимі, і при запуску демо завантажує їх у [RRAM](../2-1_rram.md) за допомогою внутрішнього аналога [UPLOAD_RAW](upload_raw.md) (загалом 612 байтів). Дані спрайтів під час гри не змінюються, змінюється лише позиція їхнього виведення (координати **X** та **Y**) у SPB.

Ігрове поле складається з кількох простих команд 2DPT із використанням [RECT](2dpt-rect.md) та [FILL_ROUND_RECT](2dpt-fill_round_rect.md) / [FILL_RECT](2dpt-fill_rect.md). Самі індикатори рахунку також є прямокутниками [FILL_RECT](2dpt-fill_rect.md) у відповідних місцях залежно від поточного значення.

Під час кожного оновлення кадру демо розраховує нове положення м'яча та ракеток, оновлює три SPB, а також повністю перебудовує весь фоновий плейлист 2DPT. Тут також можна було б спростити алгоритм і перезаписувати лише ті слоти, що відповідають зміненому рахунку. Демо не використовує апаратну перевірку зіткнень від 2dfx; сама логіка вираховує перетин прямокутників та змінює координати X/Y м'яча.

Коли один із гравців здобуває очко (м'яч вилітає за межі поля іншого гравця), ігрове поле труситься. Цього ефекту досягнуто зміною [SET_XY_OFFSET](2dpt-set_xy_offset.md), що значно простіше, ніж перераховувати та завантажувати нові значення **X** та **Y** для всіх відповідних слотів 2DPT. Оскільки [SET_XY_OFFSET](2dpt-set_xy_offset.md) стосується виключно плейлиста 2DPT, помітно, що спрайти не дрижать разом із полем.

У «Pong» можна пограти на «Enterprise» або «TVC» за допомогою короткої програми на [BASIC](../../../programming/is-basic.md): змінюючи значення відповідних бітів порту [F9h](../../../programming/system-info/ports/port249.md) під час роботи демо, ми сигналізуємо про початок нової гри або напрямок руху відповідної ракетки. Сигнал руху потрібно скидати при відпусканні клавіші! Ось програма на BASIC для Enterprise, яка забезпечує керування:

```basic
100 PROGRAM "pong.bas"
110 SET KEY RATE 1
120 SET KEY DELAY 1
130 SET KEY CLICK OFF
140 SET £102: PALETTE 0,73,75,219,146,182,109,255
150 OUT 248,80                    ! Ініціалізація 2dfx
160 OUT 249,1                     ! і активація режиму ENGINE_ON
170 WAIT DELAY 2
180 OUT 248,199                   ! Виклик гри  
190 LET A$=INKEY$
200 IF A$="q" THEN OUT 249,8      ! переміщення лівої біти вгору
210 IF A$="a" THEN OUT 249,4      ! переміщення лівої біти вниз
220 IF A$="p" THEN OUT 249,2      ! переміщення правої біти вгору
230 IF A$="l" THEN OUT 249,1      ! переміщення правої біти вниз
240 IF A$="n" THEN OUT 249,128    ! запуск нової гри
250 IF A$="" THEN OUT 249,0
260 GOTO 190
```

**Підсумок:** це демо є простим прикладом того, наскільки мало даних насправді потрібно змінювати для формування ігрового екрана. Після того, як дані трьох спрайтів один раз потрапляють у RRAM, під час гри змінюються лише кілька координат та рахунок; ігрове поле 2dfx формує на кожному кадрі за допомогою лише кількох команд 2DPT.
